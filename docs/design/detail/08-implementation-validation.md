# 08 实施任务、集成场景与验证设计

本文件是 [详细设计入口](README.md) 的执行清单，阶段对应 [概要实施路线](../06-delivery.md)。读取 [AGENTS.md](../../../AGENTS.md)，确认受影响接口和调用方，再按单元交付。当前已完成P1最小工程骨架的Windows smoke；下列其余场景仍是未来需要运行的场景和预期，尚无业务CMake目标、真实Runtime或已通过的产品测试。
推荐算法的评审编号在 [00](00-contract-baseline.md) 唯一维护。不能看到一个表就认为相关安全/公共语义已获批；也不能无限搁置，用已确认边界内的完整切片持续推进。

## 2. 实施工作单元

| 单元 | 范围/前置 | 交付 | 实际验证出口 |
| --- | --- | --- | --- |

| IM-03 | Core与D-DOMAIN/PERMISSION | Registry、Workspace、Session、Message、权限规则 | 领域转换/增量/授权失效的真实单元场景 |
| IM-04 | D-DATA，05 | Store端口、工作区/会话/消息保存、配置、迁移恢复 | 重新打开、写失败、冲突、真实旧数据迁移 |

| IM-07 | IM-02/03，D-UI/EVENT | 实际桌面页面及Client/VM、消息/任务/权限交互 | 实窗创建、切换、取消、关闭晚到结果 |
| IM-08 | 04及工具权限 | MCP发现/调用、Tool路由、Skills有效配置和Native明确范围 | 实际可控MCP与真实Runtime能力映射 |

编号不是强制串行顺序：IM-02/03共享接口先统一；IM-04/05/09基础可独立，UI客户端按已确认合同实施；最终必须集成。Native的真实执行需求不能用“首Runtime已接入”替代，其未实施范围明确列出。

每个工作单元需具体列负责文件、依赖的公开合同、状态与资源拥有者、输入失败/取消路径、调用方迁移和实际验证；不能把一个超长Manager分给多人各写一段。

## 3. 文件与构建目标落地

根据各层文件建议创建必要目标，依赖图由真实CMake表达：公共契约可独立编译，Core不包含具体Adapter/UI头，Backend无UI可运行，Desktop只负责组合。第三方告警与自研策略分离。

每次变更统计手写源码/头/测试/脚本物理行，500行上限，超过300行检查职责；C 80列目标/100列上限。避免宏/实现片段/机械part文件绕过。新公开符号查询引用后同步调用方，不以兼容别名暂留冲突接口。

源码出现后应登记配置、构建、测试、静态分析、资源检查和真实程序启动命令及平台前置条件；现阶段不填写虚构preset或测试名。

## 4. 可控场景设施

| 设施 | 必须可控制的行为 | 不能替代 |
| --- | --- | --- |
| 时间源 | 单调时间推进、同截止边界的完成/取消排序 | 真实系统时钟平台验证 |
| Provider测试替身 | 受理、分片、重复/迟到事件、断连、取消确认、不支持能力 | 任何正式Runtime或Native实现 |
| 本地子进程 | stdout/stderr并发输出、部分写入、退出、忽略优雅停止 | 实际厂商协议兼容 |
| 临时Store/目录 | 分配/写入失败、旧版本数据、损坏与权限错误 | 用户真实数据/凭据 |
| 受控MCP服务 | 发现、调用、失效、畸形/超大消息与断连 | 全部生产MCP兼容声明 |
| UI测试数据源 | 快照与增量交错、页面销毁后结果、能力变更 | 实际UI操作与真实Runtime链路 |

测试中采用确定的调度顺序/可控时钟，不用sleep碰运气；不把错误注入钩子暴露为生产绕过安全的开关。

## 5. 跨层Given/When/Then场景

### INT-01 工作区到真实会话

Given：已授权临时工作区、实际版本Runtime可用。When：用户创建Workspace、启动/连接实例并创建Session。Then：工作区与会话关联正确，可用状态只在外部与要求的存储事实确认后显示；失败路径不遗留受管资源，诊断ID可定位。责任：FE/BE/CORE/RT/DATA/EXEC。

### INT-02 流式结构化消息

Given：含文本与受支持内容块的会话。When：增量被拆帧且多会话交错。Then：每块归属正确、重复revision不重复追加、Tool Result关联到对应Call；不支持内容明确拒绝，完成/保存状态独立可见。校验实际界面和已保存记录，不只检查事件计数。

### INT-03 受理与资源失败

Given：入口复制或队列额度可失败。When：复制失败则拒绝；受理后Store准备失败。Then：前者没有request_id/后续完成，后者有唯一Failed且没有外部副作用；所有临时内存释放。禁止将受理响应误当已发送。

### INT-04 完成/取消/截止竞争

Given：共享00推荐状态机已评审、可控单调时间。When：分别安排成功先处理、取消确认先处理、deadline已到后才处理成功。Then：各产生一次对应终态；cancel_requested本身不是Cancelled；deadline优先检查；迟到外部事实只更新execution/cleanup，不把TimedOut改Succeeded。结果必须与已批准合同一致。

### INT-05 快照交接与重同步

Given：页面OpenView尚未安装快照。When：同scope状态更新并有事件到达，再制造订阅队列满。Then：基线前状态不重复应用，后续sequence不丢失地应用或明确ResyncRequired；重新OpenView取得当前事实，不无限缓存、不假称完整。

### INT-06 页面关闭与退订

Given：UI Queue有未处理载荷且回调正在执行。When：切页/销毁并Unsubscribe。Then：接收代次失效，队列载荷释放、不访问旧控件；仅close-complete后回收callback context，回调内退订不自等待死锁；业务任务不因关页面被偷偷取消。

### INT-07 权限范围与失效

Given：具体Workspace/Session/Runtime/Tool请求等待批准。When：错误关联答复、有效拒绝、有效一次批准、批准后策略revision变化分别到达。Then：错误/过期不执行，拒绝终结，批准仅授权相同目标且执行前重查；Runtime未提供控制能力明确提示，不能伪装已沙箱化。

### INT-08 外部ID与连接代次

Given：两个Runtime都返回相同外部request_id，某实例重连后再次复用ID。When：旧回调晚到。Then：实例+generation隔离正确，旧结果不命中新请求，不挂到“当前会话”，映射最终释放。

### INT-09 执行成功但保存失败

Given：外部消息已真实执行，完成写入失败。When：Backend收尾或应用重启。Then：execution_result与persistence_status不被合并为假成功/假回滚；需要持久成功的用例报告失败但不再次盲执行；已有请求终态不能二次改变。

### INT-10 MCP/Skills/工具

Given：有实际可控MCP服务、可校验Skill和明确工具执行者。When：发现/授权调用、服务断开、无效Skill、保存启用但Runtime应用失败。Then：发现不等于授权、断连使能力失效、无效内容不执行，期望配置与实际生效分开；原生Runtime工具不冒充Aether执行/完整审计。

### INT-11 日志与错误响应

Given：DEBUG采集且输出可用。When：真实业务失败，用户复制ID并查询。Then：能关联边界、错误码、耗时和清理；秘密不出文件/UI，普通根因不层层重复。另测INFO过滤、切级别/重启/CLI覆盖、队列满/不可写、unfinished；日志故障不修改业务错误。

### INT-12 应用关闭与平台

Given：运行中存在Session、权限等待、管道、查询、日志写入。When：应用关闭或初始化中途失败。Then：新提交拒绝，已有资源按所有权收尾，UI不阻塞，无UAF/泄漏，不误杀借用进程；关闭截止到达仍有明确资源所有者。在Windows/macOS/Linux分别观察，不从一平台推断另两者。

## 6. 任务验收引用

各层局部用例分别维护在FE、BE、CORE、RT、DATA、EXEC、OBS章节；本文件只描述整合场景，避免复制断言。实现者把每个变更映射到局部用例和至少一个相关INT场景，不能只选成功路径。

完整产品还需逐页验证Runtime/Workspace/Session、消息/任务、权限、MCP/Skills/工具、配置/凭据、诊断等操作矩阵。局部场景通过不能掩盖未实现菜单；核心原则是功能、错误、取消和退出均可观察。

每次报告：阶段范围、文件/职责、接口与所有调用方、运行平台/Runtime版本、实际命令或UI步骤、预期与实际、资源/错误结果、未验证项。源码关键字检查只能检查文档/结构，不证明行为。
