# 00 跨层契约详细设计基线

## 1. 状态与适用规则

本文件维护跨层设计与实现理由。DEC-04/06的边界见ADR-0004；DEC-05请求/事件语义已纳入[接口契约](../../INTERFACE_CONTRACTS.md) §4.4、§10.4及ADR-0005，不再在本文维护第二套状态表。其他未确认模型仍为推荐，不是已发布ABI；现行架构/接口/工程规范优先。

本轮应给出具体方案供评审，而不是要求实施 AI 再自行设计所有语义。各层不能私自替换本基线的请求状态、快照交接、资源释放或 ID 作用域。未列错误名不自动扩充 AetherStatus，具体错误仍映射现有状态类别加业务代码。

## 2. 身份、数据与执行域

### 2.1 逻辑身份

| 身份 | 推荐语义 | 禁止混用 |
| --- | --- | --- |
| provider_id | 一类已注册 Runtime Provider | 不等于进程或连接 |
| runtime_id | 一个运行/连接实例；对应现有事件字段 | 不使用产品名称作为实例身份 |
| connection_generation | 同一实例每次建立新连接的代次 | 外部 request/session ID 必须与实例及代次合用 |
| workspace_id / session_id / message_id | 持久领域身份，创建后稳定 | 不由当前页面位置或可变显示名决定 |
| request_id | Backend 实例代次内一次已受理应用请求的身份 | 客户端重发、Session、trace 不是它 |
| event_id / sequence | 事件身份与订阅交付序号 | 不承诺数据库序号或跨订阅总序 |
| trace_id / span_id | 独立操作及子操作身份 | 不授权，不替代业务标识 |

建议外部 DTO 将逻辑 ID 表达为有界 UTF-8 不透明值；内部按类型隔离，禁止任意混传。具体编码/长度、持久 ID 生成及 Backend 实例代次表示由 D-ID 评审；算法失败显式返回，不复用别的请求身份。Adapter 仅在自己命名空间持有外部 ID。

### 2.2 C 数据与内存契约建议

- 字符串输入使用只读指针和字节长度，UTF-8；长度非零时指针不可空。路径、二进制内容与可显示文本分别校验，不假设都以 NUL 结尾。
- 入口同步校验时借用调用方数据；若操作受理，Backend 在返回前完成所需复制，复制失败不受理。不会把所有 Core 内部调用强制深复制。
- Query 快照/异步结果交给调用方的是独立 DTO 所有权，提供配套释放函数；失败输出初始化为空。采用统一内部 allocator 时由创建模块的释放接口回收，不能跨库猜测 `free`。
- 事件回调仅借用事件载荷至回调返回；Frontend Client 需要排入 UI Queue 时复制所需载荷，或使用正式发布的显式保留接口。首选单次有界复制，不默认引入全项目引用计数。
- 业务 DTO 不含 TraceContext、Logger、UI 指针或库句柄。RequestContext 独立携带已验证元数据；跨任务复制小型只读值，可变任务对象不随便复制。
- IO 结果、业务状态与 UI 状态分别由自己的执行域修改。推荐应用状态单一串行执行域；IO 回调投递有界事实消息，不直接改领域对象。线程数/库由 D-EXEC 选择，执行域不等同于固定线程数量。

## 3. Command受理与请求实现交接

请求状态、deadline与取消竞争、查询保留及顺序示例统一见[接口契约§10.4](../../INTERFACE_CONTRACTS.md#104-请求终态与等待交接dec-05)。Backend实现顺序为有界校验/输入复制和额度预留→原子登记入队→状态域重查→Core/Provider执行→有效事实回状态拥有者→一次逻辑终态→独立清理。失败受理不能产生request_id或后续完成通知；不要用Runtime的yield/message_end替代请求结果。

实现理由：Pi实际客户端超时撤销的是等待，不发abort；OMP先登记collector再写入以容纳早到结果，并只用本请求prompt_result完成等待。Aether同样区分等待与执行，增加自己明确的单调业务deadline和权威结果保留。不要将第三方SDK超时默认为Aether业务截止，也不要把取消确认等同OS资源关闭。

## 4. 快照、订阅与事件实现交接

正式OpenView、revision/sequence、失效、回调线程及退订保证唯一维护于[接口契约§4.4](../../INTERFACE_CONTRACTS.md#44-视图握手与回调交接dec-05)。Backend在同一串行状态操作建立快照/订阅边界；Client先登记可存活receiver，再发送OpenView；UI安装快照后应用有界缓存。不另做无关联Query/Subscribe握手，不建持久重放系统。

Backend与UI两级队列都需关闭；VM先失效，独立callback context等close-complete和本地引用解除后回收。回调不持状态锁，不能同步等待自身退出。订阅满载用独立健康状态表达ResyncRequired，不向满队列硬塞错误；重新打开只重建读模型，不重放业务副作用。容量由DEC-11实测。


## 5. 域对象及响应交接

Core 只更新领域对象；Backend 将领域事实映射 DTO 并协调请求终态；Adapter 管协议解析和外部映射。Session/Message 的状态表在 [Core 详细设计](03-core.md) 唯一维护，Backend 不复制第二份。

错误分类继续使用现有 AetherStatus，业务代码进一步细分参数边界、冲突或 stale revision；新增类别需改正式契约。推荐安全响应包含 code、可展示 message、request_id（若已受理）、trace_id（若可用）、相关结果/保存状态；具体签名不在此冻结。

日志与业务事件分别输出，Logger 失败不改变领域结果；文件写入失败可能改变用例“保存成功”结果，不能把二者混淆。数据执行事实与持久化事实的交接见 [数据与配置](05-data-config.md)。

## 6. 评审项索引

| 编号 | 本套推荐设计的范围 | 批准/收敛要求 |
| --- | --- | --- |
| D-ID | ID 区分、编码、代次和唯一性 | 类型/生成失败/三平台证据，公共契约评审 |
| D-EXEC | 状态串行拥有者与 IO/工作执行域 | 调度库/线程选型、关闭顺序和压力证据 |
| D-REQUEST | 正式受理/取消/deadline/终态见接口契约§10.4 | DEC-05已收敛；APP-07运行状态和竞争验收 |
| D-EVENT | 正式OpenView/序号/退订见接口契约§4.4 | DEC-05已收敛；APP-08验证握手、失效和关闭 |
| D-DOMAIN | Session/Message/Runtime 状态及并发策略 | Core 模型及 Provider 能力评审 |
| D-DATA | 逻辑记录、写入边界、恢复/迁移 | 存储选型、数据完整性评审 |
| D-PERMISSION | 策略组合与临时授权 | 安全边界和无法强制控制的产品行为确认 |
| D-PROTOCOL | 目标 Runtime/MCP/Skills/Native | 实际版本资料、执行范围和兼容性证据 |
| D-UI | UI 框架与事件循环桥接 | 实窗、C 绑定、跨平台和可访问性验证 |
| D-LIMIT | 队列/记录/输入/存储/查询容量 | 给出有限配置值及边界测试，不写无界默认 |
| D-DIAGNOSTICS | ID格式、编码/输出/查询及级别配置 | 与追踪契约一致，脱敏/故障验证 |

这些是设计议题编号，不是新的已接受 ADR。实施某一模块前只收敛其依赖项；不要求先批准无关未来功能，也不能借尚未确认的设计跳过安全或资源约束。
