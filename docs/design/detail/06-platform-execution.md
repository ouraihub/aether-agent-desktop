# 06 进程、异步执行与跨平台详细设计

## 1. 边界与设计状态

本文件承接 [基础设施概要](../05-infrastructure-platform.md)，细化资源及算法。推荐方案待 D-EXEC/D-LIMIT 评审，未指定 libuv、线程数量、沙箱或操作系统最低版本。硬约束见 [架构](../../ARCHITECTURE.md)、[工程规范](../../CODING_STANDARDS.md)；应用请求终态遵循 [00](00-contract-baseline.md)，本层不裁决用户请求成功。

## 2. 执行域与数据结构

| 对象 | 推荐内部数据 | 归属 |
| --- | --- | --- |
| ExecutionService | 接收状态、有界任务队列、执行器引用、在途计数、关闭状态 | 组合根创建，服务自己管理资源 |
| WorkItem | 请求关联、只读Context副本、owned输入、完成投递目标、取消观测 | 接收成功后任务服务负责释放；失败仍归提交者 |
| ProcessRecord | 不透明进程身份、owned/borrowed、OS句柄、stdout/stderr/stdin状态、退出事实、关闭计数 | Process Service，不向Core暴露句柄 |
| ConnectionRecord | 实例/连接代次、读写缓冲、截止/取消、回调及寿命状态 | Network或Process服务 |
| TimerEntry | 逻辑任务身份、单调deadline、generation、投递目标 | Timer服务；不指向可随时释放的业务栈 |
| ResourceCloseState | close_requested、pending_callbacks、实际关闭事实 | 单一资源拥有者；不是Request状态副本 |

推荐状态执行域串行处理业务事实，IO域只观察系统结果；昂贵/阻塞工作交工作执行器。物理线程/循环配置按目标框架验证，不能一层自动建一线程。任务队列溢出显式拒绝，不能偷偷同步执行到UI线程。

## 3. Process Service 接口意图

| 操作 | 输入/输出 | 行为边界 |
| --- | --- | --- |
| spawn | executable、argv、cwd、environment allowlist、管道配置、Context → Process身份 | 参数列表不是任意Shell拼接；启动失败清理全部局部句柄 |
| attach_connection | 实际连接描述 → owned连接 | 不获得既有外部进程的终止权 |
| write | Process/Connection、只读字节视图 → 受理/字节交付结果 | 完成前复制/保留有效数据，短写继续，不把受理当全部已写 |
| request_stop | 受管身份、已确认策略 → 停止协调结果 | 协议取消先由Adapter处理；本层不假造协议指令 |
| observe_exit | 回调/查询 → 原始退出事实 | 正常退出码不自动等于业务成功，交Adapter解释 |
| close | 资源身份 → 异步close-complete | 关闭pipe与进程退出分别确认，之后才允许释放回调上下文 |

输出状态使用标准错误类别并保留平台原始诊断于受控内部信息；不向用户暴露完整命令、环境或路径。

## 4. 创建、读写与退出算法

### 4.1 创建

校验配置和已授予执行范围 → 预分配记录/回调上下文 → 创建所需管道 → 创建进程 → 注册stdout/stderr并行读取和退出观察 → 返回受管身份。任一步失败只关闭已获得资源；若进程已创建而后续注册失败，按受管清理策略终止/等待并报告，不丢失句柄。

可执行文件与参数来自受控配置，动态输入不能改变解释为Shell程序。Windows参数编码与POSIX argv组装由Platform实现，准确保持空参数、引号和Unicode，不在Adapter自己拼接。

### 4.2 管道处理

stdout和stderr都持续读取，分别有界缓冲；Provider协议数据进协议解析器，stderr默认诊断元数据，不直接回显敏感正文。处理短读、半帧、EOF、读错误与进程已退出但pipe未EOF的情形。

写队列有总字节与条目上限；调用者通过明确完成结果得知全部交付或失败。取消排队写入与已经部分写入分别报告，部分外部副作用不能回滚。不得因为stderr不关心就不读，从而阻塞子进程。

### 4.3 退出与关闭

推荐本地资源状态：Creating、Running、StopRequested、Exited、Closing、Closed、Failed（创建/资源失败）；Exited指进程事实，不意味着所有pipe回调已经结束。

停止流程为停止接受新写入 → Adapter按协议请求优雅停止（如支持）→ 受管停止截止 → 经批准的强制终止策略 → 等待退出和pipe关闭 → close-complete。外部借用连接只关本方连接，不杀进程。

进程树/孙进程行为必须定义并实测：Windows可评估Job Object、POSIX可评估受管进程组，这些仅是候选机制，不是沙箱保证。共享Runtime的单请求取消绝不默认走进程树终止。

关闭超时通过控制面报告，资源仍由服务保管，不能释放仍在回调里的对象；应用终止政策须明确是否继续等待、受限关闭或强制结束整个受管应用，不能隐藏遗留执行。

## 5. 网络、计时器与取消

Network端口定义目标类别、请求大小、响应上限、单调截止、TLS/代理等适用配置。支持取消但不假设取消能撤回已发送远端操作；证书验证不能默默关闭。

Timer触发携带任务ID与generation，接收方先查在途关联；取消计时器不等于已投递回调被回收。过期任务不访问旧指针。业务请求deadline与IO自身超时分开，均由对应所有者解释。

取消令牌推荐为寿命受控的任务状态或向拥有者投递取消事实，不能用跨线程普通bool无同步读写。选择原子/锁/消息方式由D-EXEC确定；纯同步内部操作不为未来统一性引入复杂令牌框架。

## 6. Platform 能力表

| 能力 | Windows需验证 | macOS/Linux需验证 | 上层合同 |
| --- | --- | --- | --- |
| 路径与文件 | UTF-16边界转换、重解析点、大小写/系统目录 | UTF-8/文件名字节处理、符号链接、目录/权限 | 输入编码与规范化结果明确，不仅比较前缀 |
| 进程 | 参数编码、Handle继承限制、Job/退出观察 | argv/env、描述符继承、wait/进程组 | 不泄漏资源，不因环境默认继承泄漏凭据 |
| 时间 | 系统单调源与墙钟转换 | 系统单调源与墙钟转换 | deadline/耗时用单调，展示用墙钟 |
| 线程与同步 | 所选库/原生接口行为 | 所选库/原生接口行为 | 不默认C threads.h处处可用 |
| 凭据数据库文件 | 应用目录访问控制、SQLite锁与sidecar/备份权限 | 目录/mode、SQLite锁与sidecar/备份权限 | ADR-0012普通SQLite明文JSON；不可用显式拒绝，无系统安全后端/加密回退；文件权限不隔离同用户进程 |
| 文件替换与锁 | 替换/共享访问/多实例锁语义 | rename/fsync/锁语义差异 | 保存成功/持久性强度与崩溃行为必须说明 |

表内系统设施是调查候选，不批准某个API组合。公开头文件采用C类型/不透明句柄，OS扩展只在Platform实现文件。

## 7. 文件访问与权限落实

请求包含授权目标与受控资源标识；执行前由权限合同复核，再解析路径到允许范围。对于符号链接/重解析点和TOCTOU风险，优先评估基于目录/文件句柄的访问机制；无法提供必要限制时报告不满足，不能用字符串校验伪称强隔离。

打开与删除/写入应分别授权，错误映射保持权限拒绝与IO失败区别。文件内容/完整路径默认不记日志。由Runtime自行发起且不经过本服务的访问不受此保障。

## 8. 组合根与构建建议

构建目标建议按公共契约、Core、Backend、Adapters、Infrastructure、Platform、Frontend和Desktop组合根隔离；公共头/编译依赖检查能证明Core不链接UI或具体Runtime。无需每个helper一target，不为动态插件创建ABI。

启动依赖顺序：Platform与基础错误/时钟 → 必要存储配置/诊断/执行服务 → Provider与Core → Backend → Frontend。失败按已成功步骤反向释放；日志后端可能尚不可用，启动错误要有安全最小报告路径。

关闭时先阻止新业务，收尾任务/Provider/订阅，后关闭共享执行、存储、日志和Platform资源。日志消费者/生产者的实际寿命决定相对顺序，不能简单按文件名倒排。后台任务join等待不得发生在UI回调。

工程建立后锁定编译器/CMake/库版本及真实预设，开启C17与严格警告；本文件不虚构已经可运行的构建命令。

## 9. 具体检查场景

| 用例 | Given / When | Then |
| --- | --- | --- |
| EXEC-01 | 管道已创建、spawn失败 | 所有句柄关闭，输出无半有效Process |
| EXEC-02 | 子进程同时大量写stdout/stderr | 两路被消费，缓冲有界，不因未读死锁 |
| EXEC-03 | 进程退出但仍有pipe回调 | 不提前free，close-complete后才释放 |
| EXEC-04 | 取消共享Runtime一个请求 | 不直接终止其他Session的进程 |
| EXEC-05 | 借用外部服务后关闭连接 | 外部服务不被杀死，本方资源已释放 |
| EXEC-06 | deadline触发后任务已替换generation | 旧计时回调不影响新请求 |
| EXEC-07 | 路径含链接/Unicode/越界 | 按平台合同允许或拒绝，不靠前缀假隔离 |
| EXEC-08 | 队列满或应用关闭中提交 | 明确拒绝，输入所有权未丢失，UI不阻塞 |
| EXEC-09 | TLS失败或凭据存储不可用 | TLS不关闭验证；凭据显式失败且无空值/旧缓存/ENV回退。ADR-0012普通SQLite明文是批准后端而非失败降级 |

每平台使用可控进程/本地服务实际运行并检查资源。仅在Windows运行不构成macOS/Linux验证，具体测试任务见 [08](08-implementation-validation.md)。
