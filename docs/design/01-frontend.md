# Frontend 概要设计

## 1. 定位与阅读入口

Frontend 把统一业务能力呈现为桌面工作平台，负责用户交互和可解释的状态展示，
不是 Runtime 控制器、领域状态拥有者或日志文件读取器。当前没有 UI 实现。
布局与主题按用户要求严格参考Autorail实际源码；[工作台设计及Token](ui/README.md)含HTML预览、PNG和逐项来源，不是GTK产品实现。模型服务配置保留Autorail分栏、字段顺序与编辑交互；GTK4选型/实测边界见ADR-0009，不以设计预览替代DEC-09验收。

规范依据：[开发入口](../../AGENTS.md)、[架构](../ARCHITECTURE.md) §2–5、
[接口契约](../INTERFACE_CONTRACTS.md) §3–11、§13、
[工程规范](../CODING_STANDARDS.md) §3–4、§6–7。
阅读路径：[总览](README.md) → 本文 → [Backend](02-backend.md)。
领域含义见 [Core](03-core.md)，能力来源见 [Runtime 与工具](04-runtime-tools.md)，
配置与诊断实现见 [基础设施与平台](05-infrastructure-platform.md)，
选型、容量和跨层交付门槛统一见 [实施与验收](06-delivery.md)。

## 2. 桌面信息架构

建议以应用导航、当前工作区上下文、主要内容区和按需详情区组织界面；
任务、权限与诊断可用页面或面板实现，不要求固定栏数，也不建立通用插件布局系统。
所有页面都有加载、空数据、查询失败、数据过期及无权限的明确表现，不能混成空列表。

| 区域 | 用户可见内容与操作意图 | 重要边界 |
| --- | --- | --- |
| 工作区 | 列表、当前选择、目录与配置摘要，创建或打开工作区 | 工作区选择是 UI 状态；目录有效性和访问范围由 Backend 验证 |
| Runtime | 实例、版本、连接与运行状态、能力，按支持情况启动、连接或停止 | 显示受管进程与借用连接区别，不能把断开连接描述为终止外部进程 |
| 会话与消息 | 按工作区组织会话，展示所属 Runtime、历史与消息编辑器 | 切换视图不改会话归属；关闭会话是独立业务命令 |
| 任务 | 请求对应的在途工作、终态、失败与取消入口 | 只呈现 Backend 已提供的任务，不提前建设自动化或 Agent 编排 |
| 权限 | 待处理请求、目标操作、来源、作用域、状态及能力缺口 | 弹窗不是授权本身，不默认提供“永久允许”等未定义选项 |
| MCP 与工具 | 服务连接、工具来源、可用性、输入要求和调用结果 | 区分 Aether 执行与 Runtime 自有工具，登记不等于接管执行 |
| Skills | 可发现技能、来源、适用范围、启用或配置状态 | 展示与操作依赖真实能力，不假定所有 Runtime 可统一安装或执行 |
| 配置 | 应用、工作区、Runtime、会话的适用配置与有效值来源 | 编辑草稿与已生效值分离，保存失败不显示成功；秘密字段不回显原值 |
| 日志与诊断 | 关联 Trace ID、筛选记录、时间、耗时与缺失提示 | 经 Backend 有界查询，不读取日志文件，也不从日志推断业务状态 |

工作区、Runtime、会话、任务和权限详情之间通过公开标识导航；全局提示应带来源，
点击后定位对应对象，而不是把背景会话的事件展示成当前会话的操作结果。
没有实现的产品区域应在交付范围中明确，不以可点击的空壳页面冒充已交付能力。

## 3. 模块职责与状态归属

建议按实际页面职责落位于 Frontend 内部，保留以下逻辑边界，不要求一行对应一个目录。

| 模块 | 持有内容与责任 | 不承担的职责 |
| --- | --- | --- |
| 应用壳与页面 | 导航、窗口、焦点、布局、页面创建和关闭 | 业务事务、Runtime 协议和后端资源销毁 |
| 展示组件 | 消息块、状态标记、输入控件、权限卡片、错误提示 | 私自查询数据库、直接提交底层工具调用 |
| ViewModel | 本视图 DTO 投影、选择项、输入草稿、分页、加载和提交状态 | 复制领域状态机或裁定业务终态 |
| UI Adapter | 隔离所选 UI 库，控件绑定、UI 调度及显示资源释放 | 引入第二条业务入口或 Runtime Adapter 逻辑 |
| Backend Client | 调用公开进程内契约，持有请求关联及订阅，移交 DTO 到 UI Queue | 业务编排、自动重试、预建 IPC/网络客户端框架 |

同一业务状态以 Backend 返回的领域投影为依据；ViewModel 是可替换的显示副本，
不能因本地按钮变灰就推断任务已停止，也不向 Backend 传递窗口或 ViewModel 指针。
输入草稿、折叠状态与当前选择归 Frontend；领域配置及其持久化归下层。
Backend Client 的待处理请求记录用于交付回调，不成为第二个任务注册表。
UI 库边界之外的自研业务仍遵循 C17；按职责拆分，避免形成巨型页面控制器。
代码长度与行宽沿用工程规范的 500 行上限、300 行职责审查及 80/100 列要求。

## 4. Backend 交接与初始化一致性

建议按页面需要协商工作区/Runtime/会话列表、消息分页、任务、权限、能力、配置、
诊断等 Query 投影，以及对应 Command 和 Event；这里不是现存或已发布的 API 清单。
DTO 只携带业务字段，RequestContext 单独携带请求元数据和显式 TraceContext。
每次独立用户操作建立自己的追踪关联；后台结果保留原关联，不借用“当前会话”。

页面初始化不能简单“先查询、后订阅”，否则会漏掉两者之间的变化。
建议与 Backend 评审一个最小一致性交接方案：在同一状态拥有者处建立订阅，
取得带该订阅作用域基线的快照，再交付基线之后的变化；若先到事件需暂存，
其容量、所有权和溢出行为必须明确。此建议不承诺全局序号、持久化或事件重放。
只有正式契约确认该方案后才按此实现；也可采用已证明等价的原子初始化方案。

ViewModel 安装快照后仅应用对应作用域的新变化；重复事件按事件身份和契约处理，
不能把跨会话序号排序当成全局顺序。分页查询也须与消息更新的基线语义一致。
出现缺口、失效或缓冲溢出时显示“需同步”，通过 Backend 定义的重新同步流程修复，
不继续宣称当前数据完整，也不自行拼凑一个持久事件总线。
切换筛选条件或对象后，旧 Query 结果不得覆盖新视图；建议使用视图请求代次关联。

## 5. 能力驱动与权限呈现

操作可用性综合当前对象状态、能力报告及适用权限；未知、查询失败、不支持、
已知支持但当前不可用需要分别解释。Backend 仍执行最终校验，按钮状态不是安全边界。
流式输出、图像输入、模型选择、工具、Skills、恢复和取消等按能力启用，
不以 Runtime 名称写判断分支；能力失效时更新显示，并处理已打开编辑器中的不兼容输入。

权限请求展示具体操作、Workspace/Session/Runtime/Tool 关联及授权范围，
只提供契约允许的决定；提交后等待 Backend 确认，重复点击不产生新的授权含义。
取消、关闭、退出或超时使请求失效时，已打开的卡片同步失效；迟到响应仍由 Backend 裁决。
明确标识 Aether 可控制的执行、Runtime 原生权限交互及无法拦截的内部操作，
不能声称统一权限界面能限制不经 Aether 的 Runtime 行为。

## 6. 消息流、多会话与任务反馈

消息视图按结构化内容块展示文本、图像、文件、工具调用、工具结果及结构化数据；
未知块显示明确的受限呈现，不静默丢弃或执行其中内容。附件访问经 Backend 授权入口。
流式增量按 Session、Message、内容块和契约规定的请求作用域归并，
工具结果按调用关联定位；不能向“当前最后一条消息”无条件追加。

建议以有界批次更新可见内容，历史分页按需加载；合并增量必须保持内容语义与顺序，
不能丢失完成、错误或权限事件。队列满和慢 UI 的策略在跨层契约确定后实现。
滚动阅读历史时保留用户位置，以未读变化提示新内容；切回会话可从查询重建投影，
不要求所有历史消息或每个会话的全部控件永久驻留内存。

发送动作区分提交中、拒绝、已受理、进行中与 Backend 确认的终态；这些是展示阶段，
不是另立领域枚举。发送失败保留可恢复的输入，不把未受理草稿当作成功消息。
取消先展示“取消请求中”，最终结果取自后端；等待超时不等于 Runtime 或进程已停止。
同一 Runtime 多会话与多个 Runtime 并行时，消息、任务、草稿和取消目标均按关联隔离。

## 7. 错误与诊断入口

错误以稳定错误码映射安全提示，附可复制 Trace ID；不可用时明确说明，
不透传底层路径、SQL、命令或原始协议错误。正常取消与失败、超时分开展示。
错误定位可跳转相应任务、会话或 Runtime，再以 Trace ID 打开日志筛选。
诊断页支持 operation/layer/component/level 筛选、时间与耗时、分页或数量限制；
默认显示 INFO 及更严重记录，DEBUG/TRACE 的采集级别与显示筛选分开。
级别设置显示持久偏好及临时覆盖后的有效值；过滤、轮转或未采集导致缺失时说明原因，
不把查不到记录解释为没有错误。日志只是横切诊断功能，不是应用首页的全部设计。

## 8. 页面与应用生命周期

页面创建先建立 ViewModel 和可撤销的结果接收关系，再启动初始化查询与订阅；
初始化失败释放已取得资源，并保留可操作的错误显示，不能遗留半注册回调。
页面销毁先禁用交互、使接收身份失效，再退订和撤销视图侧等待；
这不等于关闭 Session 或取消业务任务，后两者必须由独立命令表达。

建议由存活时间受控的 Client/投递记录持有 DTO，UI Queue 按接收身份和代次查找页面，
而不是持有页面裸指针。退订期间排队或正在执行的回调按正式契约排空或丢弃并释放载荷；
仅检查已释放对象里的“已销毁”标志不安全。回调上下文须等明确释放条件满足后回收。
应用关闭由组合根协调业务停止与 UI 退出；UI 不阻塞等待，先停止新操作，
解除前端订阅和投递依赖后再释放 UI 资源，不自行杀死借用的 Runtime 进程。

## 9. 实施前问题与本层验收

实施前与 Backend 明确：初始化基线、事件缺口处理、分页一致性、请求及实例标识作用域、
内容块与流式终态关系、取消/关闭行为、退订后的回调保证、授权选项及配置生效反馈。
UI 方案还需证明事件循环集成、中文输入、键盘焦点、高 DPI 与可访问性可行；
具体框架、队列容量、首 Runtime 与平台证据按 [交付门槛](06-delivery.md) 决策。

验收应在真实桌面 UI 操作：选工作区和实际接入的 Runtime、创建会话、发送消息、
观察流式或明确的非流式响应与终态，并从一次失败定位诊断 ID；此链路只验证进展，
不能替代工作区、配置、工具、Skills、权限、任务等全部已承诺范围的验收。
另覆盖能力未知/不支持、权限拒绝/失效、多会话同时输出、取消竞争、快速切页、
查询与事件交错、销毁后晚到回调和关闭应用，确认无串会话、假成功或悬空访问。
UI 自动化和契约测试可使用明确标识的模拟源制造竞态；真实 Runtime 与真实 UI 场景
分别记录平台、版本和结果，模拟通过不冒充真实接入，也不推断其他平台已验证。
