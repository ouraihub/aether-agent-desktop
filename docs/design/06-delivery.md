# 跨层流程、实施路线与整体验收

## 1. 适用范围

本文把 [项目总览](README.md) 及各层设计转成整个 Aether 的集成任务。路线承接 [总规范](../设计2.0.md) §21，不替代 [AGENTS.md](../../AGENTS.md) 的开发合同；所有名字均为设计意图，当前没有可执行工程命令。

实施遵循公开契约优先、一次明确目标、真实行为验收。某层或阶段完成不能宣称项目完成；没有真实 Runtime 或 UI 时可交付已验证基础能力，但必须报告对应前置条件，不能用替身冒充完整产品。

## 2. 启动与关闭

### 2.1 启动

1. 应用组合根读取启动参数，初始化必要 Platform、基础错误/时钟及日志能力；失败须有真实错误路径，不假设 logger 已可用。
2. 打开配置/存储，检查版本和必要迁移；解析 `secret_ref` 指向的 credentials 数据，计算非秘密有效设置。按 ADR-0012，持久凭据后端为普通 SQLite 非加密 JSON，而非系统安全存储；不可用拒绝依赖操作，不以空值、旧缓存或 ENV 回退，不自动读取外部凭据。失败不能静默清空数据或降级成“加载成功”。
3. 创建领域服务及注入依赖，装配 Runtime Provider、工具/MCP/Skills 服务。按用户配置及明确策略连接或启动 Runtime，不擅自启动所有候选。
4. 启动 Backend API、任务和事件分发，形成可查询初始状态；未就绪能力明确标记。
5. Frontend 经 Backend 获取快照并订阅事件。查询/订阅之间的竞态由正式契约解决，不靠启动时机侥幸避开。

部分初始化失败按已取得资源回滚；组合根管理寿命，不包办业务操作。

### 2.2 关闭

先停止新任务和新查询，明确在途任务完成/取消策略，再撤销权限等待、关闭 Session/Runtime 活动及生产事件的资源。随后完成订阅/队列收尾和约定持久化，停止 UI 结果投递，最后关闭日志和底层资源。

精确顺序依据依赖关系及所有权确定：共享服务不得先于使用者销毁，UI 不同步等待外部 Runtime，借用进程不能擅自终止。关闭超时不授权释放仍被回调使用的对象，必须明确遗留执行资源由谁接管以及用户看到什么结果。

## 3. 端到端业务场景

| 场景 | 跨层协作 | 必须处理的非正常路径 |
| --- | --- | --- |
| 新建工作区 | Frontend 提交目录/配置；Backend 校验与编排；Core 建立领域对象；Filesystem/存储端口执行 | 路径越界/失效、权限拒绝、落盘失败；UI 不直接读写项目文件 |
| 接入 Runtime | Backend 选择已注册 Provider；Adapter 核实版本/能力并使用 Process/Network；统一状态事件回 UI | 未安装、启动失败、协议不匹配、能力未知、连接断开，不伪装可用 |
| 创建会话 | 校验 Workspace 与 Runtime 能力；Core 创建 Session；Adapter 建立外部关联；存储记录必要元数据 | 本地创建成功但外部失败、部分资源回滚、重复命令、工作区关闭 |
| 发送与流式回复 | 业务 DTO 与 RequestContext 分离；Backend 受理；Core/Provider 执行；Adapter 转换增量；事件到 UI Queue | 超大/不支持内容、受理后失败、事件缺口/重复、慢 UI、持久化失败 |
| 权限确认 | Core 策略判定；Backend 发布具体权限请求；UI 经 API 回应；执行边界再次验证有效性 | 拒绝、无人响应、请求已取消、迟到/重复确认、策略变化或错误会话关联 |
| 取消或超时 | Backend 定位在途任务；Adapter 按能力转为取消；唯一状态拥有者决定终态；清理继续可观测 | 不支持取消、完成竞争、等待超时但工作继续、进程终止失败、迟到回调 |
| 工具/MCP/Skills | Registry/配置定义可用能力；Backend 协调授权；相应执行者调用/映射；统一结果回 UI | 工具消失/参数错误、MCP 断连、Skill 无效、Runtime 内部执行不可拦截 |
| 历史与恢复 | Backend 查询存储快照；UI 展示内容；恢复请求经能力判断与 Adapter 实际执行 | 历史存在但 Runtime 不支持恢复、外部会话过期、数据迁移失败；禁止自动重放任务 |
| 错误诊断 | 原错误保留并映射安全响应；TraceContext 贯穿边界；Backend 受控日志查询 | 日志过滤/轮转/故障导致不完整，诊断 ID 不可用，不能反推业务成功 |
| 多 Runtime/多 Session | 各实例及会话独立关联，Backend 协调活动与 UI 选择 | 相同外部 ID、连接重建、事件交错、关闭一方影响其他方，禁止共享“当前请求” |

场景跨层发生，但源码只能依赖 [架构规范](../ARCHITECTURE.md) 允许的公开边界。原始事件不直接进入 ViewModel，日志不成为业务状态的权威来源。

## 4. 先把接口交接说清楚

| 交接点 | 详细设计必须完成的内容 | 消费方验收 |
| --- | --- | --- |
| Frontend / Backend | DTO、Command/Query/Event、请求上下文、订阅和查询快照关系、响应资源释放 | 页面切换、并发和退订后晚到事件不会错写状态 |
| Backend / Core | 用例与不变量分工、状态所有者、错误、事务及配置生效边界 | 无 UI 可运行，同一领域规则不在应用层复制 |
| Core / Provider | 能力、Session/请求关联、取消/关闭/错误与事件语义 | 替换 Adapter 不修改领域主体，不支持功能显式失败 |
| 应用 / 存储 | 数据模型、写入时点、查询一致性、事务与迁移/恢复合同 | 失败不误报已保存，不丢历史、不自动重放外部副作用 |
| 权限 / 执行边界 | 作用域、继承/冲突、授权有效期、用户交互及执行前复核 | 确认只能授权对应目标，Runtime 无控制能力时明确缺口 |
| 业务 / 基础设施 | 字符串/对象寿命、线程和关闭行为、容量/背压 | 无跨栈借用、无关闭后回调，资源成对释放 |
| 业务 / 诊断 | root/span、错误与业务事件区分、查询权限、日志故障 | 并发不串 trace，敏感信息不出日志，错误仍可传播 |

字段和状态码只在 [接口规范](../INTERFACE_CONTRACTS.md) 维护。公开 API 改动先查引用、确定受影响调用方并一起迁移，不以兼容别名隐藏冲突。

## 5. 分阶段任务与验收门槛

### P0：需求核实与关键选型

对照仓库确认基线，定义当前阶段范围和端到端验收；完成下文与该阶段有关的决策。候选需官方资料、许可证和目标平台验证支持，不能把建议表当批准表。

交付：模块依赖与接口评审结论、实际工具链/构建计划、首个真实验证场景及风险。P0 不是额外业务功能，也不能用不断规划替代实现。

### P1：工程基础（总规范 Phase 1）

建立真实 C17/CMake 工程、Platform 基础、统一错误与所有权、日志/追踪基础、测试和 CI。只实现必要基础能力，不自建大型类型系统或通用容器库。源码格式、500 行上限与职责审查应可执行检查。

验收：目标平台基础编译和最小程序实际运行，错误/部分初始化清理有效，单元与静态检查可执行；日志产生可查询记录但不据此宣称完整诊断 UI 已实现。缺失平台必须列为未验证。

### P2：前后端契约与最小桌面交互（总规范 Phase 2）

建立 Backend API、DTO、inproc 调用、应用任务与事件订阅、前端客户端/UI Queue。UI 框架选型先验证事件循环、C 绑定和平台支持。一个真实 Command/Query/Event 场景通过整个边界。

验收：Backend 无 UI 独立运行；实际窗口可提交操作并接收事件，后台不直接碰控件，销毁/退订路径可观测。页面仅承担当前场景，后续功能不以空按钮冒充已交付。

### P3：领域与数据基础（总规范 Phase 3）

实现 Workspace、Session、Message、Runtime Registry、必要 Agent 配置、Configuration/Permission 和领域事件。完成最小持久化及恢复语义，测试独立于真实 Runtime；结构化消息不能退化为仅有一个拼接字符串。

验收：领域不变量和状态转换、数据落盘/重新打开、失败回滚、权限拒绝有实际测试。Provider 测试替身只用于明确隔离场景；正式运行不能伪称已连接 Runtime。

### P4：真实 Runtime 纵向闭环（总规范 Phase 4）

按核实的实际版本实现首个 Adapter，串起工作区、会话、消息流、取消、异常退出、配置和诊断。第一条真实链路完成后按同一能力接口接入其他目标 Runtime，分别记录支持矩阵和限制。

原路线建议 Native 优先，不是强制选型。本设计建议优先选择有稳定可验证接口的真实 Runtime；首个顺序及 Native 的真实执行范围需确认，不能擅自把 Native 改成 Mock，也不能把“暂未实施”写成永久取消。

验收：每个宣称支持的 Runtime 实际启动/连接、收发、取消/不支持反馈、异常清理和版本能力可验证；至少覆盖多实例/多会话交错，不按 Runtime 名称写 UI 分支。

### P5：MCP、Skills 与工具生态（总规范 Phase 5）

建设实际 MCP 连接/发现/调用、Skills 元数据/校验/启停与范围、Tool Registry 及权限流程。区分 Aether 执行与 Runtime 自有能力映射，不重复替第三方实现工具执行器。

验收：真实可控 MCP 服务、工具权限允许/拒绝/超时、Skills 无效输入与生命周期、Runtime 能力映射及审计范围准确。注册成功不等于调用成功，展示可用不等于强制控制已成立。

### P6：完整桌面与产品整合（总规范 Phase 6）

完善工作区/Runtime/会话多路管理、消息和任务体验、权限交互、配置与凭据、日志诊断及运行状态展示。日志等级持久化、有效覆盖来源、Trace ID 检索/复制等纳入真实 UI 验收；同步错误、安全和资源行为。

验收：用实际应用完成 §3 业务场景，启动/关闭和故障恢复行为明确。按目标平台验证运行资源及交互，用户路径中的占位操作、假成功和未接线控件均不能作为完成。

### P7：后续演进（总规范 Phase 7）

IPC 独立 Backend、多前端、自动化任务/编排、长期记忆、数据分析、插件和远端管理各自根据实际需求形成范围、ADR 与验收。它们属于项目路线而非本轮概要中已设计完成的能力，不提前生成空模块、协议或插件 ABI。

每次用户要求交付的阶段必须明确；P1–P6 的桌面平台完成不能自动宣称 P7 完成，也不能因 P7 尚未实施将已完成阶段说成无效。

## 6. 并行任务边界

共享前置接口确认后，Frontend 与 Backend 可按 DTO/事件契约独立实施；不同 Runtime Adapter 可按 Provider 合同分别实施；存储与日志可按注入端口独立实现。它们最终必须在真实链路集成，接口 mock 的调用成功不是集成证明。

不可并行猜测的共享项包括状态定义、错误码、DTO 来源、取消语义、权限优先级和资源所有权；设一个维护者协调修改。每个子任务列出负责文件、输入契约、输出行为和验收，不把顶层设计或状态机分给多方各自重造。

## 7. 实现前决策门槛

| 决策 | 需要的证据/明确结果 | 必须在何时完成 |
| --- | --- | --- |
| 工具链/基础依赖 | 三平台编译器/CMake版本、严格警告、许可证与构建方式 | P1 配置前 |
| UI 与异步集成 | 实际窗口/后台事件、关闭、安全绑定、平台支持 | P2 依赖引入前 |
| 领域与异步契约 | Session/请求完整状态表、ID作用域、取消竞争、快照/事件一致性、背压和退订 | P2–P3 对应公开接口前 |
| 持久化与配置 | ADR-0008数据权威/短事务/迁移/生效；ADR-0012普通SQLite明文JSON凭据、secret_ref整合事务、WAL/journal/备份风险及非取证删除；ENG-07-C与DATA分别验收 | 决策已收敛，实现与运行证据仍须按任务交付 |
| 首 Runtime / Native 范围 | 官方版本、稳定接口、能力/权限限制、真实验证环境；Native 的执行职责 | P4 相应实现前 |
| 权限与强制隔离 | 威胁模型、继承/冲突、授权失效、路径校验、Runtime 控制缺口处理 | 对应危险操作和安全承诺发布前 |
| MCP/Skills/工具 | 协议版本、来源/作用域、生命周期、执行者和授权映射 | P5 接口前 |
| 诊断与容量 | Trace ID 编码、记录/队列/文件上限、轮转、日志配置、查询授权和关闭截止 | P1 基础与 P6 查询相应接口前 |
| 远端/IPC/插件等 | 实际产品需求、协议兼容、认证授权、部署成本及退出迁移方案 | P7 对应架构切换前 |

未决事项应当有明确证据与收敛时点，不能变成“TODO 实现”或在代码里默认放宽。普通实现细节可依据已有规则选择简单方案，重大取舍按 [ADR 流程](../adr/README.md) 记录，不能伪造批准。

## 8. 整体验收与证据

| 验收维度 | 必须实际观察 | 主要责任层 |
| --- | --- | --- |
| 架构边界 | 无 UI Backend 运行、公开依赖检查、新 Adapter 不改变 Core 主体 | Backend/Core/构建 |
| 真实业务链 | 创建工作区/会话、结构化输入与流式输出、工具/权限、关闭清理 | 全层 |
| 并发隔离 | 多 Runtime/多 Session/重启代次下请求、事件、trace 不串联 | Core/Adapters/Backend |
| 状态与失败 | 受理后失败、取消竞争、超时后工作继续、迟到回调、断连/异常退出 | Core/Backend/Adapters |
| 数据完整性 | 落盘失败不误报保存、迁移失败不丢数据、历史与 Resume 区分 | Backend/存储 |
| 权限与隐私 | 允许/拒绝/过期确认、越界路径、secret_ref逻辑分离与不泄日志/UI；ADR-0012明文数据库/sidecar/备份风险不冒充加密或同用户隔离，不支持强制限制时明确提示 | Core/执行边界/UI |
| 工具生态 | 实际 MCP 调用、Skills 校验启停、工具执行权和能力映射 | 工具领域/Adapters |
| 日志诊断 | 按真实错误 ID 检索层级和耗时，级别重启恢复、覆盖与脱敏、日志故障可见 | 基础设施/Backend/UI |
| 资源与性能 | 分配失败、部分初始化、关闭中回调、管道/队列/日志满载无无界增长和悬空访问 | 全层 |
| UI 可用性 | 实际窗口中的加载/空/错误/不支持状态、切换和销毁、权限及设置操作 | Frontend |
| 跨平台工程 | 每个目标 OS 的配置、编译、运行和适用资源检查 | Platform/CI |
| 代码维护 | 单一职责、500行上限、300行审查、C行宽和公开接口/文档同步 | 全层 |

永久测试聚焦真实行为、边界和不变量；测试替身用于隔离外部依赖，不冒充产品实现。功能验收还须运行具体程序/界面/协议场景，检查实际结果；未运行的平台和第三方版本明确列出。

交付证据包括实际命令或操作、平台/版本、输入场景、输出/状态、错误与资源结果，以及未验证项。仅源码字符串存在、函数被调用、编译通过或文档链接有效不能证明业务完成。

## 9. 阶段交付模板

每次实施报告：目标和阶段、修改文件及职责、接口/调用方变化、线程与资源影响、安全及数据行为、实际验证及结果、已知问题和未完成项。首次建立工程后把真实命令写入入口，不现在虚构预设名称。

向下一任务交接稳定契约和实际事实，不交付误导性空壳。若用户要求全项目交付，须明确覆盖范围和全部验收；不能用只实现聊天、日志或 Mock Runtime 的演示替代整个 Aether。
