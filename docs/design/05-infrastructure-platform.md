# 基础设施与平台层概要设计

## 1. 范围和依赖

本层为整个 Aether 提供进程、文件、持久化、配置、网络、异步执行、加密/安全存储及日志诊断能力，不负责 Session 等领域规则。当前无实现，以下组织为推荐蓝图，不表示 SQLite、libuv 或其他候选库已选定。

依赖约束见 [架构规范](../ARCHITECTURE.md) §2、§4–6；资源和错误规则见 [工程规范](../CODING_STANDARDS.md)；公开端口见 [接口契约](../INTERFACE_CONTRACTS.md)。上游是 [Backend](02-backend.md)、[Core](03-core.md) 与 [Adapters](04-runtime-tools.md)，整体阅读入口为 [项目总览](README.md)。

## 2. 能力划分与建议落位

| 能力 | 建议位置 | 主要职责与接口意图 |
| --- | --- | --- |
| Process Service | `infrastructure/process/` | 创建受管进程、管道读取、状态/退出码、取消终止与资源关闭 |
| Filesystem | `infrastructure/filesystem/` | 受控路径访问、读写和目录操作；配合权限决策落实实际执行检查 |
| Persistence | `infrastructure/database/` 或已选存储实现 | 实现领域持久化端口、事务、版本迁移、查询及资源回收 |
| Configuration Store | `infrastructure/config/` | 保存配置与读取结果，不决定业务优先级和权限继承 |
| Network/HTTP | `infrastructure/network/` | 连接、请求/响应、超时取消、有界缓冲和安全协议配置 |
| Async/Timer | `infrastructure/async/` | 执行器、任务投递、计时器及关闭协作，不另建业务状态机 |
| Logging | `infrastructure/logging/` | 统一记录、过滤、有界输出、轮转、读取及输出健康状态 |
| Crypto/Secret Store | `infrastructure/crypto/` 与 Platform | 成熟加密能力和系统安全存储封装，不手写密码算法 |
| Platform | `platform/windows/`、`platform/macos/`、`platform/linux/` | OS 句柄、路径、时钟、进程/线程、系统目录和安全能力差异 |
| 公共基础契约 | 必要 `shared/` 公开边界 | 状态、字符串视图、追踪值及可注入端口，不承载业务全局状态 |

只有真实职责才建模块。一个 `infrastructure_manager.c` 不能包办所有资源；公开端口不泄漏 SQLite/libuv/OS 类型给 Core 或 UI。通用能力接口不必全部塞进 Core，领域存储端口由使用方定义。

## 3. 数据持久化设计

### 3.1 建议的数据分区

| 数据类别 | 权威与保存目的 | 实现前必须确定 |
| --- | --- | --- |
| 工作区定义、配置引用 | Core 管语义，存储实现负责恢复可用配置 | 路径表示、删除含义、权限与配置版本 |
| 会话元数据及外部关联 | 记录所属 Workspace/Runtime、模型配置和外部会话关联 | 外部实例重启后的关联有效期、恢复能力 |
| 消息与内容块 | 保存用户可查询的业务历史，不依赖日志重建 | 增量/完成落盘时点、附件引用、保留/删除策略 |
| 在途任务和执行状态 | 内存任务为运行状态权威；是否保存快照由恢复需求决定 | 崩溃后标记 Interrupted/Unknown 等的实际契约，不能自动重放 |
| Runtime/MCP/Skills/工具配置 | 保存用户选择及启用范围 | 敏感字段、安装来源、版本与作用域 |
| 权限策略 | Core 定义决策，存储按已批准范围保存 | 临时授权是否落盘、失效和撤销，不能把一次确认永续化 |
| 凭据 | 安全存储持有；普通配置仅保存必要引用 | 平台可用性、访问失败提示、导出/迁移边界 |
| 日志 | 独立诊断输出与保留策略 | 不作为业务持久化、事件重放或安全审计的唯一来源 |

不在概要中写死表名、主键类型或 SQL Schema。存储选型前评估事务、并发访问、容量、许可证和三平台支持；若采用 SQLite，仍须显式定义连接归属与写入模型，不能默认多线程共享连接安全。

### 3.2 写入与失败一致性

推荐由 Backend 用例协调持久化边界，Core 维护领域不变量。状态通知发生于“内存接受”还是“持久化完成”必须在对应事件契约中明确；不能落盘失败仍显示“已保存”。

外部 Runtime 调用不属于本地数据库事务，不能把网络调用包在数据库锁内并假装可回滚。发送已发生但结果未知时报告明确不确定状态，不盲目自动重发。流式 Delta 可按实际需求聚合落盘，但策略、异常中断后可见内容与容量须评审并验证。

迁移必须有版本、失败处理和数据完整性验证；变更不得静默删数据或重新建库。历史展示与 Runtime Resume 是不同能力，只有真实协议支持且恢复成功才能报告外部会话已恢复。

## 4. 配置管理与安全执行

Backend 配置服务负责默认值、用户配置、Workspace/Runtime 覆盖的有效值计算及变更通知；本层只负责读取、校验所需基础能力和可靠保存。业务配置的具体优先级尚须决策，不把日志级别的已定优先级泛化到所有配置。

配置更新必须区分已保存、当前生效、需要重新连接/重启及保存失败。非法输入不能静默变成默认值；凭据不能出现在普通 DTO、日志或原样错误中。环境变量采用显式选择，不默认把宿主全部环境传给 Runtime。

路径校验必须考虑规范化、符号链接/重解析点和检查到使用之间的变化；不能只用字符串前缀当作隔离。权限决策由 Core/应用流程给出，本层在实际副作用前执行对应检查，不允许绕过授权直接操作。

第三方 Runtime 不经过本层的文件/工具行为不受这些检查天然保护；操作系统沙箱须另行确认和验证，不能因启动时指定工作目录就宣称安全隔离成立。

## 5. 进程、网络及异步资源

Process Service 接收明确可执行文件、参数列表、工作目录和受控环境；禁止任意拼接 Shell。返回的进程/管道资源明确所属实例、停止方式和回收责任，stdout/stderr 均需持续有界处理，不能因未读管道阻塞子进程。

区分 Aether 创建的受管进程与借用的外部连接；关闭借用连接不授予杀死对方进程的权限。进程树处理、优雅退出与强制终止时机、超时等待及平台差异必须发布前明确，Runtime 的取消请求不自动等于杀进程。

HTTP/网络能力定义取消、截止时间、状态与响应大小上限；证书/连接安全不能为兼容方便而默认关闭。不擅自加业务重试，副作用重放按调用方契约处理。

IO 回调将结果交回状态拥有者，不能直接修改 ViewModel 或任意领域对象。队列/缓冲必须有容量与背压/拒绝行为；具体循环和线程数量由实测选定。关闭服务前解除回调生产并等待实际资源关闭，不能释放仍被 OS/库回调持有的对象。

## 6. 日志诊断子系统

日志是本层的一项共享能力，不代替整个项目架构。接口和字段唯一维护于 [接口契约](../INTERFACE_CONTRACTS.md) §13，完整要求见 [工程规范](../CODING_STANDARDS.md) §4。

建议拆分记录封装/输出、文件轮转读取和健康状态等职责；TraceContext 与最小日志端口置于可独立依赖的公共边界。任务持有操作终结责任，日志实现不拥有 Session 或业务请求。

root/child 上下文显式随请求、队列和回调传播；C 使用明确清理路径，不依赖析构。六级过滤前不构造昂贵摘要，输出有界且敏感字段受控；过滤、轮转或写入失败造成缺失时如实报告。Backend 提供受控查询，Frontend 只展示和复制诊断 ID。

运行时级别、偏好保存及覆盖来源属于 Backend 配置流程；当前已定优先级是命令行、环境、持久化偏好、默认 INFO。具体日志库、ID 编码、存储格式与容量数值不是本概要批准项。

## 7. 跨平台工程与资源装配

组合根先创建必要 Platform/基础资源，再创建技术实现、Provider、Core 和 Backend，最后连接 UI；顺序按真实依赖而非固定目录排序。初始化失败仅清理已经取得的资源，日志也可能尚未可用，不允许因报告初始化错误而递归失败。

公开头文件不泄漏 OS 句柄和编译器私有扩展。路径编码、错误码映射、系统目录、时间与资源关闭在 Platform 统一处理；第三方语言绑定在独立边界配置，不侵入 C17 业务代码。

工程需提供真实 CMake 目标、平台预设、依赖版本/许可证清单和 CI。静态检查、内存/资源工具按平台支持安排，未在目标 OS 运行不能声称三平台可用。文件长度/行宽遵循 [AGENTS.md](../../AGENTS.md)，不能为满足限制把资源所有者拆散或隐藏实现规模。

## 8. 本层验收与交接

- 存储：真实保存和重新打开，验证部分写入/失败/迁移、消息与外部关联、删除权限及数据不会被静默清空。
- 配置：无效值、保存失败、重启恢复、生效范围、凭据不可见及环境过滤。
- Process/Network：可控进程/服务覆盖 stdout/stderr、异常退出、超时取消、资源关闭、借用连接和受管资源差异。
- 异步与平台：部分初始化、在途关闭、迟到回调、队列满和路径越界均有实际结果；UI 不阻塞。
- 日志：实际请求可检索 trace、并发不串链、脱敏与不可写故障；不以 logger 被调用作为完成证据。
- 目标平台分别报告编译、运行、资源检查及未覆盖能力。

待决定的库、存储/配置合同、容量、线程、关闭截止与安全机制进入 [实施与验收](06-delivery.md) 的决策清单。向 Backend/Core 交付的是稳定行为端口，不是具体库句柄。
