# ADR 0006：首个工程切片的有界容量基线

- 状态：提议（未获项目负责人确认；DEC-11前置决策尚未全部完成，不作为ENG-05实施许可）
- 记录日期：2026-11-08
- 决策依据：DEC-11；Pi/OMP/Autorail容量调查；`docs/design/detail/00-contract-baseline.md`、
  `docs/design/detail/06-platform-execution.md`、`docs/design/detail/07-observability.md`；
  当前Aether已验证的Foundation/Backend/Platform实现。
- 替代关系：补充ADR 0004/0005的资源边界；不冻结未来完整产品容量或真实Runtime协议上限。

## 容量提议

以下为待评审起始值，尚不是生产默认值；32条任务/64 KiB输入/16 KiB记录/1秒关闭须结合前置决策和真实负载确认，不能因写入本文即实施：

| 资源 | 初始值 | 满载/超限行为 |
| --- | ---: | --- |
| Foundation错误消息 | 159字节内容 + NUL | 设置失败，输出清空 |
| Backend本地请求记录 | 8条 | 新受理返回容量错误，不静默驱逐 |
| Platform路径 | 由ENG-04平台表示边界约束，不是4096字节产品限制 | 返回明确错误，不截断 |
| ENG-05任务队列 | 32条 | 投递显式拒绝；不在调用线程偷偷执行 |
| ENG-05任务输入 | 64 KiB | 投递前拒绝；调用方仍拥有未受理输入 |
| 单条诊断记录 | 16 KiB | 截断或拒绝按日志实现契约标记，不写无界字段 |
| 关闭等待 | 1秒优雅等待 + 控制面报告 | 不释放活跃回调；强制终止由具体受管资源任务批准 |

## 规则

- 条目数和字节数同时受限；任何新增队列/缓存须声明两者及失败行为。
- 关键完成、权限、取消和控制健康事实不能因普通Delta溢出被静默丢失；订阅溢出进入ResyncRequired，权威状态可查询。
- RequestRecord终态保留期、日志总量/轮转、消息/附件/快照分页上限仍由各后续任务在真实需求和平台证据下确认；本ADR不伪造这些值。
- 单调时钟用于deadline/耗时；墙钟只用于展示和记录。
- 关闭先停止新生产、发起优雅收尾并等待有限截止；截止后资源仍由拥有者保管，close-complete前不释放回调上下文。ENG-05只提供任务服务基础，不实施Process Service的强制终止。
- Pi/OMP/Autorail的1 MiB/64 MiB帧、256页、14天日志等仅为参考证据，不直接复制为Aether协议或产品容量。

## 批准后所需验收

若批准上述数值，ENG-05须验证队列/输入边界、取消意图与实际停止分离、generation防晚到、关闭拒绝新工作、部分初始化及释放。正式ENG-05还必须交付计时器，不得以只有任务队列的切片标整项完成；验证用可控时间/顺序，不用sleep碰运气。
