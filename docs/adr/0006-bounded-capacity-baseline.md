# ADR 0006：首个工程交付的有界容量基线

- 状态：已接受（DEC-11工程起点，不是吞吐/SLA或全项目内存实测）。
- 日期：2026-11-08；补充ADR-0004/0005/0008/0010/0011。
- 依据：用户要求明确决策参考Pi/OMP直接落定；DEC-04/05/06/08/10已收敛。实际OMP18.18.0 ready确认1MiB物理/64MiB逻辑帧；参考日志真实context/过滤场景通过。
- 边界：数值是可调整但有限的初始配置，不把参考项目所有常量原样复制。后续实现须覆盖边界和故障，不因设计表存在而标记工程任务完成。

## 1. 工程基线

所有KiB/MiB按1024计算；“且”为两个上限同时满足。队列的字节数含其持有的所有可变载荷及包装，不含已单列固定元数据；共享正文只由明确所有者计一次。乘法/加法溢出先拒绝，不截断或回绕。数值必须可由构造配置降低供确定性边界测试，不因调大配置变无界。

| Foundation错误/现有请求登记 | 159字节+NUL / 8条 | 保持已发布合同，不改旧同步API容量或偷偷驱逐 |

## 2. 日志与诊断子预算

DEC-10日志/诊断数值唯一完整表见[ADR-0010 §5](0010-local-diagnostics.md#5-初始容量与解释同步dec-11)，包括记录/队列/优先预留、构造scratch、批写、实例/全用户文件配额、最长保留、Query工作量及游标。满载丢新记录并计health/drop，重要记录也不承诺零丢失。日志文件与业务库/附件分别计配额；本ADR预算引用该表，不另设不同默认。

## 3. 预算及容量理由

选择小型桌面起点：32排队×64KiB=2MiB，不把参考64MiB逻辑RPC帧复制到每个任务；4MiB消息/32MiB活动聚合限制流式长输出，同时附件流独立。OMP真实64MiB上限只保留一份全局重组额度，而非四实例各无限积压。页默认100而上限256，参考OMP分页又保持1MiB响应双限；低命中日志扫描另有工作量限制。

显式载荷峰值保守求和：任务2MiB+4运行输入256KiB+事实8MiB+请求元数据1MiB/输入8MiB+权限512KiB/64KiB+16订阅32MiB+UI4MiB+活动消息32MiB+Store排队2MiB/3连接6MiB/pending4MiB+4连接读缓冲1MiB/写4MiB+全局重组64MiB+日志队列/元数据4.0625MiB、writer0.0625MiB、2查询2.375MiB、16游标0.015625MiB、8producer0.375MiB，共**175.703125MiB**；另留64MiB供完整逻辑JSON解码/映射临时空间、16MiB供有界快照，合计**255.703125MiB**，组合根初始受管载荷池预算取**272MiB**，逐项预留，无法同时满足则拒绝而非额外malloc绕开。临时数据也须占池；不能因求和有余量而无限分配。

这不是全进程RSS上限：第三方JSON/SQLite内部、UI渲染/字体、OS缓存、线程栈另计；初始后台最多8线程、每线程栈保留上限1MiB（平台可行性由ENG-05确认），Core静态记录及依赖内部也须实测。UI框架尚有DEC-09验收门槛，不虚构渲染预算。后续负载若要求更多并发，变更同一容量配置、预算和回归证据，不隐式增长。

## 4. 状态责任与实施验收

- 关键请求终态、权限等待、关闭/取消状态由权威对象保存，订阅可失效但不得丢唯一状态责任；控制门独立于满队列。输入/额度先取得再受理，OOM不产生幽灵request。
- 单调时钟用于保留/过期/deadline；墙钟只展示和日志保留。默认业务deadline可由明确API配置覆盖，不能把SDK等待超时当业务超时。
- ENG-05必须同时实现任务、取消观测、代次、计时器和关闭；DATA实现配额/迁移备份，APP实现字节双限/原子受理，ENG-09实现日志真实轮转/健康。每项都用降低的容量、可控时钟和可控事实验证刚好上限/上限+1、释放重用、算术溢出、迟到和部分初始化；不靠sleep碰运气。
- 改值是工程调优而非向用户反复询问；有负载证据时记录原因、峰值和失败策略。不改变权限语义，不把满载伪装成功。
