## 状态与变更规则

- **提议**：存在实际决策议题及备选方案，尚未确认；不能作为实施许可。
- **已接受**：有明确批准或既有规范依据，记录来源和日期；不能伪造批准人或把推荐方案追认为已批准。
- **已拒绝**：记录不采用的理由，防止反复提出同一方案。
- **已替代**：链接后续 ADR，后续记录也指回被替代记录；保留历史理由，不将旧决定改写成新决定。

文件名采用 `NNNN-short-title.md`，编号不复用。记录至少包含状态、记录日期、决策依据、背景、决策、理由、替代方案、影响、风险与替代关系；追记须明确标注，不能把记录日期当作历史批准日期。

重大变更先说明取舍并由项目负责人确认，再将提议置为已接受，同步当前规范、接口与调用方。发现现行规范与 ADR 冲突时明确指出，不按文件时间自动推断谁覆盖谁。

## 尚无已接受决策的事项

具体 UI 框架、libuv 等异步库、JSON/数据库/加密库及其版本、线程数量与事件循环集成、队列背压、权限继承与沙箱、首个 Runtime 与实际协议版本、独立 Backend/网络传输均未在此获批。对应证据与决策时点见架构专题 §9，接口发布前语义见接口专题。

不为每一个候选方案预建“已接受”ADR，也不为凑编号创建空提案。实际开始相关选型时，才形成包含可比较方案与证据的记录。
