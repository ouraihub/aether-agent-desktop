# ADR 0001：自研业务代码采用 ISO C17

- 状态：已接受（既有规范决策追记，不代表构建已验证）
- 记录日期：2026-11-07
- 依据：项目总规范明确的 C17 定位、技术栈与阶段目标，以及用户要求建立 C17 工程规范；本次拆分没有重新批准语言选型。
- 当前规则：[CODING_STANDARDS.md](../../CODING_STANDARDS.md) §2
- 替代关系：无前置 ADR；统一此前总规范中与 C17 定位冲突的 C11 残留表述。

## 背景

Aether 是面向 Windows、macOS、Linux 的新建桌面项目。需要统一自研代码的语言模式，并避免公共接口依赖编译器扩展。原文同时出现 C17 与 C11，容易使 AI 生成不一致的构建配置。

## 决策

自研业务代码采用 ISO C17；核心不使用 C++，平台/UI 必要语言绑定隔离。CMake 显式要求 C17 并关闭语言扩展；第三方 Runtime 的实现语言以及第三方依赖的内部构建标准独立管理。

## 理由与替代方案

C17 主要修正和澄清 C11，没有引入新的编程模型。现代桌面项目没有已知的旧工具链强制兼容需求，保留 C17 与现有项目定位一致。

C11 可在实际必需工具链不支持 C17 时重新评估，但目前没有该约束的证据。C23 和 C++ 不是本次项目选型，不因“更新”而引入额外迁移范围。

## 影响与风险

公共接口、源码和构建要求一致；C17 不保证可选标准设施在所有平台均可用，也不自动保证线程库兼容。最低编译器版本、标准库组合、严格警告支持仍须建立工程后验证，不能以本 ADR 代替三平台构建结果。

如真实目标工具链迫使标准变更，新增 ADR 明确替代本记录，并同步工程规范、构建和全部受影响接口。
